# Motivation

传统的深度推荐模型有三个缺点：

+ **特征缺乏显示结构**：推荐系统的海量特征缺乏明确的结构，如果想要充分挖掘和利用它们之间的语义关系、组合逻辑，需要很强的人工特征工程。同时很难自然地映射为transformers擅长处理的结构。
+ **需要处理十亿级别的动态词汇表**，在训练和推理阶段带来巨大的挑战。
+ **计算成本高**：推荐系统每天需要处理的tokens数量比语言模型在1-2月内处理的数量还要大几个数量级
+ **持续增大模型规模和数量级不会给推荐模型带来显著提升**



# 对推荐问题的重塑

##统一的特征空间

**HSTU将各种各样的特征编码（类别特征和连续特征）为统一的序列**



![\<img alt="" width="478" height="479" data-attachment-key="SV3NCHIT" src="attachments/SV3NCHIT.png" ztype="zimage"> | 478](assets/SV3NCHIT.png)



类别特征（稀疏）：首先选择宽度最长的序列作为主时间序列（绿色），其他特征作为辅助序列

+ main time series（主序列）：通常由**user-item交互对**组成，$(\phi_0, a_0), (\phi_1, a_1), \dots$，其中$\phi_i$代表用户交互的item，$a_i$代表交互的动作（点赞、收藏、加购等），这些交互对**严格按照时间戳排序**，组成了主序列。
+ 辅助序列：由**随时间缓慢变化的类别特征**构成，为**每个连续不变区间保留最早的一个条目**来压缩这些时间特征，然后将结果**合并到主时间序列**中，由于这些时间序列**变化非常缓慢**，**这种做法不会显著增加整体序列长度**。

数值特征：传统的深度学习模型会构造大量的统计特征，与类别特征相比，这些特征的变化频率高，从存储和计算的角度看，**这些特征不可能完全序列化**，但是**数值特征本质上就是对类别特征的统计结果，使用大规模长序列建模和目标感知的建模方式可以代替使用聚合统计特征**。

## 重新定义召回和排序

经过上一步处理得到了

+ 按照时间顺序排列的tokens序列：$x_0, x_1, \dots, x_{n-1}$ 
+ 用户行为类型序列：$a_0, a_1, \dots, a_{n-1}$ 
+ 观测时间序列：$t_0, t_1, \dots, t_{n-1}$ 
+ 其他数据



![image-20260208160216752](assets/image-20260208160216752.png)

召回

学习概率分布$p(x_{i+1}|u_i)$，它的含义是**在$t_i$时刻给定用户表征向量$u_i$学习整个底池的item的概率分布，学习目标是选择概率最大的$x_{i+1}$来最大化推荐系统的某个指标。**

与NLP的自回归任务（当前所有词的生成概率依赖于之前以生成的所有词）不同

+ **$x_{i+1}$不是监督信号**，因为用户对$x_{i+1}$不一定是正反馈。
+ **$x_{i+1}$可能是类别特征不一定是物品，此时$y_i=∅$**



排序

排序通常要进行**target-attention**建模**，候选物品要与历史物品做交叉，且越早越好**，**但如果推荐系统内也采样标准的自回归任务建模，交叉只能在encoder输出后接softmax层进行，无法再encoder内部底层提早做交叉，效果上大打折扣**。

因此，**HSTU不止在建模item序列，而是建模(item,action)交替序列，通过过往信息预测下一个action，$P(a_i|\Phi_i, \Phi_{i-1}, \dots, a_0, \Phi_0)$，在action位置不预测**。



# 模型结构



![image-20260208161437800](assets/image-20260208161437800.png)

与Transformer类似，**HSTU由L个相同的模块堆叠而成，每个模块包含三个子模块**，将DLRMS的特征提取、交互、变换融合到一个可堆叠的模块中。

## Pointwise投影层

$$
U(X), V(X), Q(X), K(X) = Split(\phi_1(f_1(X)))
$$

 **参数解释**： 

+ $X \in R^{N \times d}$：输入序列，$N$是序列长度，$d$是维度 - $f_1(X)$：单层线性层。
+  $U(X)$：用于“压缩并携带”用户的长期序列的最原始的表征。 
+ $\phi_1$：SiLU激活函数。 
+ $Split$：$f_1$函数输出一个$N \times (hd_q + hd_k + 2hd_v)$的tensor，Split将其拆分为$Q \in R^{h \times N \times d_q}$，$K \in R^{h \times N \times d_k}$，$V \in R^{h \times N \times d_v}$，$U \in R^{h \times N \times d_v}$。 

**核心内容**：在传统的Q、K、V的基础上，额外增加了一个U，U的作用是**压缩用户长期行为序列的信息**，保留了最原始的长序列信息。



## Pointwise空间聚合层

$$
A(X)V(X)= \phi_2(Q(X)K(X)^\top + r_{ab}^{p,t})V(X)
$$
**参数解释**：

+ $rab^{p,t}$：相对注意偏差，包含位置(p)和时间(t)信息，模型可以感知到token的相对顺序和时间间隔。
+ $\phi_2$：SiLU激活函数。 

**核心内容**： 

1. **Transformer中会采用softmax函数将注意力分数归一化为和为1的概率分布，即$\sum w_i = 1$，这样可能丢失用户的兴趣强度,不管有多少历史都归一化为1，将“用户看过很多类似内容”和“用户只偶尔看过”的差别严重压缩。**用户A看了100个item，90个衣服，10个电子产品。用户B看了10个item，9个衣服，1个电子产品。对于softmax来说，这两个用户的“对衣服的权重”是相同的，但明显用户A对衣服的兴趣强度要高于B。
2. **softmax的分母依赖于当前看到的所有token，一旦序列分布变化，归一化基准就会改变，训练和推理都会不稳定。**
3. **HSTU采用了pointwise聚合注意力机制（经典的DIN就是这种），更好地保留用户的兴趣强度。**



## Pointwise转换层

$$
Y(X) = f_2(\text{Norm}(A(X)V(X)) \odot U(X))
$$

 **参数解释**： 

+ $f_2(X)$：单层线性层。 
+ $\text{Norm}$：层归一化，用于稳定训练。
+ $U(X)$：Pointwise投影层得到的用户长期行为原始表征。
+ $Y(X)$：输出。$Y(X) \in R^{N \times d}$。 

**核心内容**：**使用类似于Moe的操作，取代了Transformer中的两个线性层和一个FFN模块**，**减少了参数量和模型计算量**。



# 工程优化

## 优化器

batch size的大小可以影响推荐系统的质量，与LLM不同，后者只需要小batch即可训练。

由于词表太大，使用row-wise **AdamW**优化器缓解内存压力，原本的Adam为每个embedding存储m,v占用了大量的内存，而AdamW让每一行embedding共享统计量。

## M-FALCON 

推荐系统中，用户历史序列长度通常服从偏态分布，在序列很长的场景下会导致输入序列高度稀疏，**作者实现了一种高效的kernel，支持不等长序列的注意力计算（无需padding）,减少了计算量,并使用fused GEMM（融合矩阵乘）避免频繁访问显存，提高吞吐量**。



## SL

**使用随机长度（SL）在算法层面增加用户历史序列的稀疏性，减少长序列带来的计算开销，推荐系统的一个重要特征是：用户行为在时间上具有重复性、多尺度性，因此可以在不损害模型效果的前提下，增加稀疏性能降低编码器的计算成本。**

将用户$j$的历史表示为序列$(x_i)_{i=0}^{n_{c,j}}$，其中$n_{c,j}$是该用户交互的内容数，令$N_c = \max_j n_{c,j}$。从原序列中构造一个长度为$L$的子序列$(x_{i_k})_{k=0}^L$。

SL的采样规则为： 

+ 若$n_{c,j} \leq N_c^{\alpha/2}$，使用完整序列；
+ 若$n_{c,j} > N_c^{\alpha/2}$，以概率$1 - N_c^\alpha / n_{c,j}^2$选取长度为$N_c^{\alpha/2}$的子序列，以概率$N_c^\alpha / n_{c,j}^2$仍使用完整序列。

经过实验，$\alpha$≈1.6–1.8 时，**算力省很多，效果几乎不掉**。
